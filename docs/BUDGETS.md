# 上下文与回复预算（2026-11-09）

## 本轮根因

旧请求与预设校验限制：上下文 2048–128000、回复 64–8192；默认 8192/1024。均为程序常量，不是模型能力信息。

用当前准备草稿和世界书的只读副本复现：必要上下文按 UTF-8 字节及消息开销估算为 12515，加 1024 预留超过 8192，在调用 API 之前即失败。此估算并非 tokenizer，中文尤其保守。

## 当前策略

- 页面默认自动；请求不传手动 budget/reserve。`server/budget.ts` 统一开场与普通回合策略。
- 未明确配置容量时，8192 仅作较早聊天裁剪目标；按必要设定、输入和最近两条历史扩展目标，不以未知模型容量的估算阻止开局。
- 裁剪只移除本次请求中的较早历史，并尽量保持用户/助手回合完整。世界设定、玩家身份和当前输入不被静默截断；原文留在 SQLite。没有新增摘要、向量检索或长期记忆系统。
- 回复未明确配置时省略 `max_tokens`，由供应商采用默认值；1024 仅是本地规划预留，不是实际输出上限，也不承诺费用上限。
- 高级用户取消自动后可以填写正整数；不再有统一模型数值上下限，仅校验正安全整数。绑定预设的明确上下文/回复值继续优先于页面值，避免静默改变导入语义。
- 手动/预设配置中回复不小于上下文时明确报冲突。历史移除后必要内容仍超限时告知本地估算、配置和调整入口，不伪装成 API 错误。
- API 返回的上下文/输出参数错误与鉴权错误分类展示；不输出供应商原始错误正文，避免反射 Key/剧情。无自动付费重试。
- Prompt Inspector 展示预算来源、输出来源、实际发送上限（null 表示省略）、省略历史条数及估算警告。

自动目标不是已核实的模型容量。API 仍可能拒绝过长请求；用户应按供应商说明填写实际容量，必要设定本身超限则需精简。无法从通用 OpenAI-compatible 模型 ID 可靠推导任意供应商的容量。

参考：[官方 Chat Completions 参数文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。输出上限是可选参数；`max_tokens` 已在 OpenAI 原生接口弃用，部分模型要求 `max_completion_tokens`。本项目手动/预设仍沿用现有 compatible `max_tokens`，没有宣称支持所有供应商参数；自动省略可避免强行注入该字段。
