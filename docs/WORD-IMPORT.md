# Word 设定导入

准备页“导入设定（Word / TXT / Markdown）”支持 `.docx`，Word 或 WPS 保存的普通 DOCX 均可尝试。正文、标题文字和表格中的文字提取到现有设定框，可检查和编辑；点击“保存准备”后随草稿保存，确认开局后成为当前存档设定。导入不调用 AI，也不会自动扩写。

这是纯文字导入，不保留字体、编号、表格布局或图片；不提供 OCR。页眉页脚、批注、修订等高级内容可能不完整，页面固定显示兼容提示，解析器警告也保留。旧 `.doc`、宏文档和加密文档不支持，请另存为普通无密码 DOCX。

文件上限2 MB，解压总量上限12 MB、最多1000个条目，这是本机文件处理保护，不是模型上下文限制。已取消10万字符导入拒绝：超过10万字符时完整保存为长文资料，设定框改为可选开局方向。可下载原始 DOCX 和完整提取文本；不截断、不自动摘要。

`server/document-context.ts` 提供当前基础检索：按段落边界附近分段，保存可回查的字符位置；首段加与开局方向/最近剧情/当前行动相关的片段进入请求。中文双字词和英文词按文档内稀有程度计分，选取量受字节预算控制，并计入原有总上下文预算。Inspector 列出实际片段、位置、总数和省略数。导入与检索不调用模型，长文不会每轮整篇发送。**这是程序化片段检索，不是 AI 语义分类，也不保证找全作者规则**；暂未建立规则/资料/示例的语义层，请在开局方向补充当前关键人物或地点。短文保持原有全文设定行为，避免改变旧存档。

实现：`server/documents.ts` 使用 [Mammoth extractRawText](https://github.com/mwilliamson/mammoth.js#mammothextractrawtextinput) 的纯文字路径（BSD-2-Clause），不用 HTML 渲染。用 [yauzl](https://github.com/thejoshwolfe/yauzl)（MIT）先检查 ZIP 条目并受限解压，拒绝重复路径、宏和自定义 XML 实体，不向磁盘解压，也不加载外部链接。依赖仅安装在项目内。

`POST /api/documents/word?name=...` 接收二进制文件，成功后将原始字节保存在 SQLite `source_documents`；准备页提供下载原件入口。`source.documentId/format/warnings/text` 随草稿和存档保存，修改提取文本不会改原件。废弃导入目前仍留在本地数据库，尚无单独文档清理界面。

验证（2026-11-09）：类型检查、构建、48项自动测试通过。`tests/documents.test.ts` 覆盖中文/段落/转义字符/表格、超限与损坏拒绝、保存准备与开局、原件逐字节下载、零模型调用。浏览器在1440/375/320px验证 DOCX 导入→开场→互动→修正→刷新恢复，没有页面错误或横向溢出。Browser 插件不可用，使用已安装 Playwright，API 路由到隔离内存数据库与模拟模型，未改用户存档。截图和脚本在仓库外 `D:\酒馆\ui-evidence\docx-*`。

长文回归：超过10万字符的 DOCX 完整导入、重启后全文保留、末尾线索检索、实际请求未发送全文，均通过。浏览器同样在1440/375/320px跑通长文导入和开局，证据在仓库外 `D:\酒馆\ui-evidence\longdoc-*`。未用真实付费模型测试检索质量。
