# 产品需求

YunoTavern：本地优先的开源文字游戏，面向希望直接导入作品、使用自有 API 游玩的读者。

Spend tokens on storytelling, not infrastructure.

MVP 包含 JSON V2/V3 卡导入、关键词世界书、流式聊天、SQLite 存档、API 配置和 Prompt Inspector。验收流程为导入卡、选择角色、新建游戏、发送一句话、看到流式回复、刷新后恢复原文。

本阶段暂缓桌面安装包、多人、自动世界模拟、摘要记忆、Tool Calling 和完整预设兼容。长期以作品原样复用为目标，逐步扩大格式兼容并公开差异。

# 开发优先级更新（2026-11-09）

当前定位为 Agent 驱动的开放式互动小说，不是 SillyTavern 复刻。优先验证“少量设定 → 开场 → 持续互动 → 有依据的故事状态 → 玩家修正 → 重启继续”。SillyTavern 是兼容输入来源，已实现的能力保留；不再以复刻全部原生功能为产品主线。保留字段不等于执行字段。完整增量顺序见 DIRECTION-REVIEW.md。

本轮已实现一句话/TXT/Markdown 开局，不强制卡片；同次生成状态增量，玩家可查看引用与修正，正常回合一次请求。验收采用本地模型服务十轮回放，以及桌面/窄屏浏览器完整流程。模型的语义判断仍可能错误；尚未实现自动摘要、Word 导入、NPC 后台调度，也未证明长篇比直接聊天更省 Token。

## 当前增量验收

世界书和角色卡可分别新建/导入，存档选择至少一类资源组合开局。角色卡可编辑基础字段，不扩写、不丢未知字段、不重写旧聊天。多个 API 连接可在 Windows 加密保存 Key，刷新后继续使用，支持替换和删除；不向浏览器回传已保存密钥。世界书属于应用资源组合，不等同酒馆世界书格式本身。

世界书也支持基础编辑：名称、世界设定/开场、关键词条目。验收要求与角色卡一致：保存后下一轮使用新内容，已有存档消息与分支不改写，未知高级字段保留，生成期间不允许改动共享资源。

当前创建体验：没有现成卡片的玩家可在既有新建流程中输入少量背景、可选身份和开场，创建并进入故事或仅保存作品；不强制标题和复杂字段，不自动生成内容。验收包括直接进入存档、实际请求包含用户填写内容、刷新可恢复、简单与高级编辑共用原数据结构。

本轮验收调整：新存档必须先准备并确认非空开场，再自由互动；支持已有卡片备选开场、简单设定、存档玩家身份、主动生成与保存准备。旧剧情不可因准备流程被改写。详见 OPENING-FLOW.md。
